# 离线语音记账

Paraformer-zh 经 sherpa_onnx 生成文本；后续拆分使用本地规则和个人备注历史，无网络推理。

## 分类推荐

1. 采用正文中明确口述的“分类XX”。
2. 检索对应收入或支出模式下的全部历史备注，优先较长的字面名称；支持去掉括号分店名后的名称。不采用自动同音纠错。
3. 将匹配的商家备注从用途上下文中移除，再分析本次具体商品或用途。例如“盒马买纸巾”按日用推荐，“小象买菜”可沿用个人历史类别。
4. 没有独立用途时，按各类别的历史次数和最近记账日期计算推荐权重。第一候选权重至少为第二候选的1.5倍才自动填入；否则保留其他并展示最多三个候选供核对。
5. 没有历史匹配时采用通用用途词库及购物、餐饮等兜底规则。

备注库保留每个备注的全局次数、最近日期，以及各分类各自的次数与最近日期。统计由现存账目生成，增删改账目后缓存失效；没有额外不可撤销的隐式学习数据。未经保存的草稿不进入历史。

历史备注达到200条时，拆分和分类匹配在独立isolate完成，只传递普通备注统计，避免发送备注选择器缓存的Future或阻塞界面。

## 修正草稿

原文可修改并重新拆分，手动修改过的字段会保留。类型切换会重新推荐合法分类；金额、分类、日期修正后对应警告清除。历史备注仅用于分类与备注选择，不提供金额、日期或收支类型的覆盖。显式备注的关键词参与分类，但数量、工资等词不会直接改变正文的金额与收支类型。

## 模型生命周期

AppShell 在首帧显示后异步预加载模型，从其他应用返回前台时自动再次准备。前台各页面共享一份模型，手动记账、切换Tab、关闭语音弹窗都不卸载，不再有45秒闲置回收。预热合并为一个Future，与语音界面共用，避免重复初始化。首帧显示与手动操作不等待预加载完成；未准备好时打开语音页仍会显示等待提示。

录音器延迟到按住说话时才创建，预加载不请求麦克风权限，也不启动录音。关闭语音界面会停止麦克风。真正进入hidden/paused/detached状态会释放模型；短暂inactive（例如权限弹窗）不会反复卸载。返回前台时先等旧引擎清理，再准备新模型，过期结果不能影响新会话。关闭App时清理全部资源。

系统内存紧张时允许回收空闲模型，或在当前语音会话结束时回收，不立即触发重载循环。之后使用语音或下一次返回前台时可以恢复准备。预加载失败不阻断手动记账，下次语音操作或返回前台会重试。

测试覆盖首次预热、不启动麦克风、前台单例复用、页面切换与手动输入、后台释放、前台自动恢复、短暂inactive、准备中的快速往返、低内存和失败恢复，以及原有分类与草稿交互。
